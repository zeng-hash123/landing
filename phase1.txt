--------------------------------------------------
PRODUCT
--------------------------------------------------

PixelPage helps users find conversion problems on their landing page.

Core promise:

"Find out what's hurting your landing page conversions."

User flow:

Landing page
→ Signup/Login
→ Enter website URL
→ Crawl website
→ Kimi analyzes page
→ Show CRO audit
→ User sees actionable recommendations

Every user gets exactly **1 free audit lifetime**.

The user must sign up/login before accessing the audit.

--------------------------------------------------
URL ANALYSIS
--------------------------------------------------

Create:

POST /api/analyze

Input:

{
  "url": "https://example.com"
}

Validate:

- Must be http/https
- Must be a valid URL
- Block localhost
- Block 127.0.0.1
- Block private IP ranges
- Block internal hostnames
- Protect against SSRF
- Add reasonable timeout
- Limit response/crawl size

Use Firecrawl to retrieve the page.

Extract a compact structured representation:

{
  "url": "",
  "title": "",
  "metaDescription": "",
  "headings": [],
  "paragraphs": [],
  "ctas": [],
  "images": [],
  "links": [],
  "sections": [],
  "visibleText": ""
}

Do NOT send unnecessary raw HTML to Kimi.

--------------------------------------------------
KIMI AUDIT ENGINE
--------------------------------------------------

Create:

POST /api/audit

Use Kimi as:

"An expert conversion-rate optimization consultant, landing-page strategist, UX writer, and product marketer."

Analyze the website using ONLY the extracted page information.

Evaluate:

1. Value proposition
2. Headline clarity
3. Subheadline
4. CTA strength
5. CTA placement
6. Above-the-fold clarity
7. Trust signals
8. Social proof
9. Feature/benefit communication
10. Page structure
11. Copy clarity
12. Conversion friction
13. Differentiation
14. Overall UX/content hierarchy

Return strict JSON.

Schema:

{
  "overall_score": 0,
  "summary": "",
  "categories": [
    {
      "name": "Headline",
      "score": 0,
      "severity": "critical|high|medium|low",
      "problem": "",
      "why_it_matters": "",
      "recommendation": "",
      "current_copy": "",
      "suggested_copy": ""
    }
  ],
  "top_priorities": [
    {
      "title": "",
      "severity": "critical|high|medium|low",
      "reason": "",
      "recommendation": ""
    }
  ]
}

Rules for Kimi:

- Be specific, not generic.
- Base findings on actual page content.
- Never invent facts.
- Never fabricate testimonials.
- Never fabricate customer logos.
- Never fabricate statistics.
- Never claim a conversion improvement percentage without evidence.
- Give concrete copy replacements where appropriate.
- Prioritize high-impact changes.
- Keep recommendations concise and actionable.
- Do not rewrite sections that are already strong.

Use server-side JSON validation with Zod or equivalent.

If Kimi returns invalid JSON:
1. Attempt safe parsing/repair.
2. Retry once if necessary.
3. Return a graceful error instead of crashing.
